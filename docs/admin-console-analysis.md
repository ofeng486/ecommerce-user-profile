# 电商用户画像系统 — 管理端（Admin Console）功能实现成果分析

> 分析日期：2026-08-07
> 分析范围：`backend/`（Spring Boot 3.3.7）与 `frontend/`（Vue 3 + TS）已实现代码
> 结论口径：以代码实际实现为准，非规划文档

---

## 1. 管理端整体定位与核心职责

管理端（Admin Console）是系统的**「系统管理者 + 数据生产者」**角色，与 User 门户（运营分析员，画像数据消费者）形成互补闭环：

| 维度 | Admin 管理端 | User 门户 |
|------|------------|----------|
| 定位 | 系统管理者 + 数据生产者 | 画像数据消费者 |
| 核心职责 | 数据生产、任务调度、画像/标签维护、运营分析、系统治理 | 画像查看、AI 分析、报表消费 |
| 关键能力 | 生成/导入数据、跑 Spark 任务、管用户/通知/审计 | 浏览画像、标签分析、AI 对话 |

管理端承担系统从「无数据」到「有数据、有画像、可分析」的**供给侧**职责：数据进得来（生成/导入）→ 算得出（Spark 任务）→ 管得住（用户/通知/任务）→ 看得懂（运营分析看板）。

## 2. 功能模块实现盘点（前端 17 个页面 / 后端 11 个接口族）

### 2.1 数据生产域

**① 数据生成（`/admin/data-generate`）**
- 核心能力：在线调用 Python 脚本批量生成合规电商模拟数据（用户/商品/行为/订单），生成后自动导入 MySQL
- 操作流程：选预设方案（快速测试 100 用户 / 默认 1000 / 中等 5000）或自定义参数（含随机种子，可复现）→ 点击生成 → 异步执行 → 历史列表查看状态/耗时/结果
- 实现效果：一键生成全量业务数据，预设一键、参数范围校验（用户 ≤5 万等）、支持一键清空全部业务数据（保留系统管理数据）

**② 数据导入（`/admin/import`）**
- 核心能力：4 类模板下载（合并主模板/高级单表/数据总表/Excel 版，中文列名 + UTF-8 BOM 兼容 Excel/WPS）+ 上传预览 + 多文件批量导入 + 天池数据集一键转换
- 操作流程：下载模板 → 填写 → 上传 → 前端即时预览（自动识别目标表、表头、样本行）→ 异步导入
- 实现效果：10 种表导入器策略化注册，文件类型/大小（100MB）/扩展名三重安全校验；天池淘宝行为、电商订单两类公开数据集免模板直接转换导入；历史任务可筛选、批量删除

**③ 任务管理（`/tasks`）**
- 核心能力：统一管理三类任务（PROFILE_FULL 画像计算 / DATA_GENERATE 数据生成 / DATA_IMPORT 数据导入）
- 操作流程：创建画像任务（任务名/数据版本）→ 状态筛选（5 态）→ 批量重试/批量删除 → 结果详情弹窗（可复制排障）
- 实现效果：固定线程池异步执行（并发 2）、状态机流转（Pending→Running→Succeeded/Failed/Cancelled）、平均耗时统计、排序白名单防注入

### 2.2 画像与标签域

**④ 画像列表 / 详情（`/profiles`、`/profiles/:id`）**
- 核心能力：画像分页查询，支持关键词、分层、省份、金额区间过滤 + 多字段排序 + 单用户画像详情
- 实现效果：CSV 导出复用列表筛选条件（UTF-8 BOM，Excel 直开）

**⑤ 标签分析（`/tags`）**
- 核心能力：消费能力等级玫瑰图、用户活跃度分布、偏好品类柱状图，数据来自真实标签分布接口
- 实现效果：品类名由后端 join product_category 直出，前端零硬编码映射

**⑥ 标签定义管理（后端已实现，前端待补）**
- 后端 `AdminTagDefinitionController`：标签 CRUD + 启停 + 仅查启用列表，接口完整
- 前端仅有 API 封装，**缺少管理界面**（详见第 5 节）

### 2.3 运营分析域

**⑦ 商品分析（`/admin/product-analysis`）**
- 指标卡（商品数/销量/销售额/均价）+ 销售 Top10 + 品类销售占比 + 价格带分布 + 头部贡献度横幅（Top10 销售额占比 + 长尾分散度提示），口径为有效订单

**⑧ 复购与留存（`/admin/repeat-analysis`）**
- 购买次数分布、复购率、平均购买间隔、月度首购留存 Cohort、高复购用户 Top10

**⑨ 流失预警（`/admin/churn-analysis`）**
- 流失等级分布 + 流失名单分页 + 流失名单 CSV 导出

**⑩ 用户聚类（`/admin/cluster-analysis`）**
- 簇分布与特征均值、簇内用户分页明细、数据版本追踪

**⑪ 智能人群圈选 / 画像对比 / 人群包（`/admin/audience/*`）**
- 圈选：多条件可视化组合（性别/分层/金额区间等字段，AND/OR 逻辑 + between 区间）、实时预估命中人数、执行圈选出结果表、保存人群包（同步落规则）
- 对比：选择两个人群包 → 年龄/性别/消费力/品类偏好雷达图多维度对比
- 人群包：列表、编辑、软删除（status 置 0）

### 2.4 系统治理域

**⑫ 系统用户（`/system/users`）**
- 分页查询、创建用户、编辑（姓名/角色）、启停、重置密码、登录审计日志查询

**⑬ 通知（`/notifications` + 顶栏铃铛）**
- 未读数 20s 轮询 + **增量弹窗提醒**（未读变多主动通知）、桌面通知授权、单条/全部已读、任务完成自动通知、通知详情可跳转（任务→任务详情、AI→总览）

**⑭ 运营数据总览（`/dashboard/overview`）**
- 状态栏（系统/MySQL/运行中任务/未读）+ 5 个 KPI（含数字滚动动效）+ 近 30 天活跃趋势 + 任务状态分布 + 用户分层分布 + 数据概况（画像覆盖率/高价值占比）+ 最近任务 + **AI 经营解读**（DeepSeek 流式）+ **运营快照导出**（TXT）

## 3. 实际业务价值

1. **数据生产从「写脚本手工造数」到「一键完成」**：默认规模 1000 用户/1 万行为约 30 秒全自动生成+入库；天池公开数据集免模板导入，省去字段对齐工作
2. **任务管理统一化**：三类任务一张表、5 态可视化、批量重试/删除，失败原因弹窗可复制，排障效率大幅提升
3. **分析闭环成型**：圈选 → 保存人群包 → 对比 → 分析看板，形成「圈人-洞察-决策」完整链路
4. **数据外溢能力**：画像 CSV、流失名单 CSV、运营快照 TXT 三类导出，直接支撑汇报与下游系统
5. **运营决策辅助**：覆盖率/高价值占比等质量指标 + AI 经营解读，帮助快速定位运营要点
6. **主动感知**：任务完成/失败的增量通知 + 桌面通知，管理员无需盯页面

## 4. 设计成果（扩展性 / 安全性 / 权限 / 易用性）

### 可扩展性
- **DDD 分层**：interfaces / application / domain / infrastructure 四层，业务与基础设施解耦
- **策略化导入器**：10 个 `AbstractCsvImporter` 子类 + `ImportTableGuesser` + Composite 总表，新增表类型只需新增 importer
- **任务模型可扩展**：任务类型为字符串枚举，新增任务类型只需扩展执行器
- **运行模式**：本地 PySpark 全链路（数据生成→画像→聚类）+ CSV/天池导入，环境适配灵活

### 安全性
- JWT 无状态认证 + BCrypt 不可逆密码摘要（数据库不存明文）
- 上传文件三重校验（MIME 白名单 / 100MB 上限 / 扩展名）
- 排序字段白名单 + MyBatis-Plus 参数绑定（防 SQL 注入）
- 401/403 统一 JSON 错误响应，无敏感信息泄露

### 权限管理
- 双角色（User/Admin），**后端 `hasRole("ADMIN")` 强制拦截 `/api/v1/admin/**` + 前端路由守卫 `meta.roles` 双保险**，且各分析/管理接口均挂在 `/admin` 前缀下受保护

### 易用性
- 预设方案一键、上传即预览（表/表头/样本行）、中文列名 + BOM 兼容 Excel
- 空态引导（"暂无人群包，请先圈选"）、操作防呆（删除需确认、重试按钮置灰并提示原因）
- 全链路异步任务 + 实时状态反馈，长任务不阻塞操作

## 5. 未完成 / 可优化项（如实说明）

1. **标签定义管理缺前端页面**：后端 CRUD 完整，前端只有 API 封装无管理 UI，标签只能由开发在库里维护
2. **双角色规划中 P0/P1 功能未落地**：数据质量监控面板、操作审计日志（当前仅有登录审计）、标签规则配置化、运营活动管理、消息推送管理——均处于规划阶段
3. **后端测试覆盖不足**：仅 17 个测试类（服务层/导入器为主），4 个运营分析服务（商品/复购/流失/聚类）与人群圈选无测试
4. **导入历史「批量重试」未实现**：系统未持久化导入参数，前端按钮已置灰并提示
5. **文档与代码不一致**：`spark-profile.md` RFM 权重（文档 30/30/40 vs 代码 40/30/30）；`AGENTS.md` Spring Boot 版本误标（4.1.0，实际 3.3.7）
6. **缺少容器化与自动化部署**：无 Docker 方案，部署依赖手工步骤；生产环境需自行配置 nginx 反代 `/api`
7. **依赖外部运行时**：数据生成/画像计算依赖本机 Python + Spark 环境，无环境时只能走演示模式数据
